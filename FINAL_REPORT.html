2. Token and cost telemetry (new)

  • What is recorded: every successful LLM call — provider, model, prompt and completion tokens, estimated cost, latency — attributed to the user command in flight (planned sub-steps share the outer command's id). Stored in the SQLite telemetry database.
  • Exact vs estimated tokens: exact counts from Groq, OpenAI, DeepSeek, Mistral, Anthropic, Gemini and Ollama when the provider returns usage. Streaming, and any call without usage, falls back to about 4 characters per token and is flagged estimated.
  • Cost is an estimate. Local models cost $0. Cloud models use rough per-provider blended rates (one table, core/telemetry/pricing.py). Set FLEXIE_PRICING_FILE to a JSON file of your plan's per-model prices for real numbers. No current provider prices were hardcoded.
  • Telemetry never breaks a call: tracking errors are swallowed (tested). Failed calls and cache hits are not recorded.

3. What was fixed

Security

  • /health no longer leaks the API token. It is issued only to allowlisted origins (FLEXIE_EXTENSION_IDS), and CORS is an explicit allowlist.
  • Permissions fail closed in ToolRegistry.execute (previously nothing checked). Approvals are single-use. Denied agent steps no longer “log and continue”.
  • python.exec cannot be told to skip the sandbox (operator policy only).
  • Confirmation matching is strict (“ok but first delete everything” is no longer consent).
  • Prompt-injection boundary: tool output is fed back as untrusted data, and after web, email or MCP content enters a turn, effectful tools (click, fill, open) need approval until the next user turn.
  • Model-generated plans are treated as untrusted: unknown tools dropped, types coerced, steps capped at 8, timeouts capped, risk never taken from the model.

Flow and architecture

  • Planner output was silently discarded by a s.command AttributeError. It now reaches AgentExecutor as a typed task graph, and handler steps honour blocked and awaiting_confirmation.
  • The controller wrapper dropped is_subcommand, silent and depth. They are now forwarded.
  • One _resolve_route: the deterministic router beats learned routes, the router runs once per command, and authoritative overrides skip the planner.
  • Specialists (P2): hard-scoped registries, a real tool loop over Brain, approvals by voice or UI, a delegate tool for the lead, whole-word routing, and fixed tag mismatches that left some specialists with no tools.
  • Memory: MemoryFacade is the single remember and forget path (forget used to leave copies in other stores). The wiki rewrite is debounced and database paths are anchored to the project.
  • Harness: RunBudget (steps, time, identical-call loop guard) on plan execution and specialist loops, agent-level evals gating CI, and evals/bench.py.
  • Portability: engines/system.py imports without pycaw, comtypes and pyautogui. The matching controls degrade instead of breaking import.
  • The hardcoded user name was replaced by FLEXIE_USER_NAME (falls back to the OS user).

Bugs found by the new evals and tests, not by reading: a plan lost to one junk step; a dependency gap after skipped steps (would deadlock); a \b regex corrupted into a backspace by an edit (caught by a test); planner tool names that matched no registered tool.

4. What is not done or not measured

Not measured

  • Plan quality, tool selection and task success with a real model. The Brain's JSON tool protocol is untested against a real (especially small local) model.
  • Real token and cost numbers: telemetry exists now, but nothing has run through it with a live model yet.
  • Any comparison with OpenJarvis or another framework.
  • Voice approval, the browser extension, desktop and browser automation, full orchestrator startup, and a GitHub Actions run.

Still open

  • Orchestrator is about 1,430 lines (the plan targets under 600).
  • Memory stores still exist side by side behind the facade (no single MemoryBackend).
  • No skill or MCP trust tiers; no per-skill capability sets.
  • Many except Exception: logging.debug blocks still hide failures; engines/ and core/handlers/ still mirror each other.
  • Safety for handler-routed steps still partly depends on user wording, not only typed tool permissions.
  • The System specialist has one tool (app.open); no desktop tools are registered.
  • Telemetry gaps: the agent_loop chat path and the model-hub Ollama call are not instrumented.
  • Loop-guard limits (20 steps, 300 s, 3 repeats) are untuned defaults.
